# Пульт Тапёра с телефона (модуль пака `remote`)

Статус: архитектура и план 16.11.2026 (Claude). Макет — артефакт «Пульт с телефона» (ссылка в отчёте сессии).
Основа — вторая док-панель (`docs/DOCK2.md` в ядре, ветка `dock2`): тот же снимок и те же команды.

## Что видит стример

1. Настройки → Модули → «Пульт с телефона» → **«Подключить телефон»**. Тапёр создаёт **сессию в интернете**
   и показывает QR-код (крупно, в окне настроек — **не на стриме**: кто отсканировал, тот управляет).
2. Телефон сканирует QR → открывается страница `https://<сайт Тапёра>/remote/#…` → через 1–2 с там тот же пульт:
   общая шапка (поиск, связь), **вкладки «Плейлист» и «Сообщения»** (это две док-панели OBS), общий подвал
   (назад / играть-пауза / вперёд, что играет, время). Телефон **вертикально** — вкладки; **горизонтально** —
   обе панели рядом, без вкладок.
3. В Тапёре видно «Телефон подключён · 2 с назад». Кнопки «Новая ссылка» (старый QR перестаёт работать) и
   «Отключить» (сессия удаляется). Сессия сама истекает через 12 ч без Тапёра.

## Как устроено (три части)

```
 Тапёр (ПК)                          облако (Яндекс или запасное)              телефон
 окно ──снимок/лента──► узел dock2 ──► модуль remote ══шифр══► функция tapyor-remote ◄══шифр══ страница /remote
       ◄──команды─────            ◄──                   (YDB: ящики,       (GitHub Pages сайта)
                                                         ничего не понимает)
```

1. **Ядро** (ветка `remote` поверх `dock2`): мост для модулей `core.remote`:
   - `dock` = `hub.forModule(id)` (снимок пульта, команды, поиск — `docs/DOCK2.md`);
   - `feed` — лента сообщений первой панели: `on(fn)` (тот же объект `widgetState`, что получает `/widget`:
     `feedHtml`, `msgCount`, `reqAuto`, `np`, `dockClass/dockStyle`), `want(bool)` (считается зрителем первой панели —
     окно начинает собирать ленту), `rq(dataset)` (как `POST /widget/rq`, окно не поднимается), `setting('reqAuto', bool)`;
   - `qr(text)` → SVG-строка (пакет `qrcode-svg`, уже есть в ядре);
   - раздел настроек `src/ui/35-remote.js` + разметка в «Модули» (как «Оверлей-плейлист»), общение — `modCmd('remote', …)`.
2. **Облачная функция `tapyor-remote`** (`server/yc-remote` в ядре, Node 22, YDB — как `yc-license`): тупой почтовый
   ящик. Видит только зашифрованные куски, не знает ключа, не знает, что внутри. Адреса облаков — списком в
   `remote/relay.json`; основное — Яндекс, запасные (на будущее, в другой стране) добавляются туда же.
3. **Пак** (`streamer-pack/remote/`): модуль в главном процессе (сессия, шифрование, опрос функции, выполнение команд
   через `core.remote`) и **страница телефона** `remote/page/` (публикуется на сайт `tapyor-web/remote/`
   скриптом `tools/sync-remote-page.mjs` — только по команде владельца).

## Безопасность

- Ключ сессии `K` — 32 случайных байта, создаёт Тапёр, живёт **только** в QR и в памяти Тапёра. В адресе он стоит
  после `#` — браузер **не отправляет** эту часть ни на сайт, ни в функцию.
- Всё содержимое (снимок, лента, команды, выдача поиска) — **AES-256-GCM**: `iv` 12 случайных байт,
  `aad = sid + '|' + вид` (`s` — снимок, `f` — лента, `e` — событие, `c` — команда), кусок = base64url(`iv ‖ флаг сжатия ‖ шифр+тег`).
  Флаг: `1` — `deflate-raw`, `0` — без сжатия; старые куски без флага читаются.
  Перед шифрованием — сжатие `deflate-raw` (Node `zlib`, на телефоне `CompressionStream`).
- Команда телефона несёт `n` (8 случайных байт) и `t` (время телефона). Тапёр отвергает: не расшифровалась,
  `t` старше 120 с или из будущего > 60 с, повтор `n` (помним последние 1000). Команды — только из белого списка
  `docs/DOCK2.md` + `rq`/`setting` для ленты (проверяет ещё и узел ядра).
- Право писать снимок и читать команды — у владельца сессии: токен `host` (32 байта), функция хранит только его SHA-256.
- Функция: лимиты частоты (на адрес и на сессию), размер куска ≤ 64 КБ (снимок/лента), ≤ 2 КБ (команда), очереди
  ≤ 50 команд и ≤ 30 событий, срок жизни 12 ч (TTL в YDB). В её лог — только виды запросов и коды ответов.
- В QR — адрес сайта Тапёра. Страница — `script-src 'self'`, без сторонних скриптов и аналитики; ленту (`feedHtml`)
  вставляет только после того, как вырежет `<script>`, `on*=`, `javascript:` (и CSP их всё равно не исполнит).
- Обложки — только `https:`; свои файлы с ПК (`/lcover/…`) телефону не отдаются (заглушка).

## Протокол функции (версия 1)

База — адрес функции (`remote/relay.json` в паке: `{ "relays": ["https://functions.yandexcloud.net/<id>"], "page": "…" }`;
старое `{ "url": … }` читается как одно облако; пусто — модуль пишет «облако пульта не настроено»).
Все тела — JSON, `sid` — 22 знака base64url (16 байт), `host` — 43 знака.

| Запрос | Кто | Тело / параметры | Ответ |
|---|---|---|---|
| `POST ?op=new` | Тапёр | `{}` | `{ sid, host, ttl }` — новая сессия |
| `POST ?op=host` | Тапёр | `{ sid, host, s?, f?, ev?: [кусок…≤10], ack?: seq }` | `{ cmds: [{ seq, c }], phoneAgo: мс\|null }` |
| `GET ?op=poll&sid=…&sv=N&fv=N&es=N` | телефон | — | `{ sv, s?, fv, f?, ev: [{ seq, e }], hostAgo }` — `s`/`f` только если новее |
| `POST ?op=cmd` | телефон | `{ sid, c: кусок }` | `{ ok: true }` |
| `POST ?op=end` | Тапёр | `{ sid, host }` | `{ ok: true }` |

`s` — снимок пульта, `f` — лента, `ev` — события (выдача поиска, toast). Номера версий `sv/fv` и `seq` ведёт функция.
`ack` — последний принятый `seq` команды (функция удаляет принятые). Ошибки — `{ error, tapyor_error }` как у других
функций (`server/common/reply.js`); 404 `no-session` — сессии нет (истекла или «Отключить»).
CORS: `Access-Control-Allow-Origin` = `PAGE_ORIGIN` (переменная функции, например `https://alexshikaka.github.io`) для `poll`/`cmd`;
для `new`/`host`/`end` CORS не нужен (зовёт Node).

Таблица YDB `remote_sessions`: `sid` (ключ), `host_hash`, `s`, `sv`, `f`, `fv`, `ev` (JSON-массив последних 30), `es`,
`cmds` (JSON-массив ≤ 50), `cs`, `host_at`, `phone_at`, `exp` (TTL). Запись — в одной транзакции (serializable).

## Список облаков и запасной канал

`remote/relay.json`: `{ "relays": ["https://…", "https://…"], "page": "https://…" }`. Старое поле `url` читается
как список из одного. Модуль при `new` перебирает облака по порядку: сессию открывает **первое ответившее**;
номер облака попадает в адрес телефона — `#<sid>.<ключ>.<номер>` (облако №0 пишется без номера). У страницы
тот же список лежит в `config.js` (его пишет `tools/sync-remote-page.mjs` из `relay.json`), облако берётся по
номеру из адреса.

Облако сессии не отвечает дольше 30 с — модуль закрывает старую сессию, открывает новую **на следующем облаке**
и показывает статус «Связь через запасное облако — отсканируй код заново». Старый QR перестаёт работать, телефон
на старом облаке видит «Пульт отключён в Тапёре». Режим Wi-Fi облака из списка не использует: у него свой
`config.js` с одним адресом (этот же сервер) и облако №0.

## Частота опроса (бережём облако)

Расписание — чистые функции `src/poll.js` (Тапёр) и `page/poll-plan.js` (телефон), проверяются тестами на
подставном времени.

- Телефон: страница видна — раз в 3 с; после любого нажатия — раз в 1 с в течение 20 с; скрыта
  (`visibilitychange`) — не опрашивает. Ошибка сети — повтор через 2 с, но нажатие всё равно ускоряет до 1 с.
- Тапёр (`host`): телефон был меньше 30 с назад — раз в 3 с, а в течение 20 с после пришедшей команды — раз в 1 с;
  телефона нет — раз в 10 с; нет телефона 2 ч — раз в 60 с. Сеть пропала — повтор 2→4→…→30 с; после 30 с
  молчания и при наличии второго облака — переход на запасное.
- Снимок и лента уходят **только когда поменялись** (подпись без времени), иначе запрос без `s`/`f`.
- Нажатие на телефоне → `cmd` сразу, затем внеочередной `poll` через 400 мс. Ожидаемая задержка 1–2 с.
- Развитие (не сейчас): WebSocket через API Gateway или прямая связь WebRTC (опыт — `tapyor-web/remote-test`),
  когда задержка 1–2 с станет мешать.

## Страница телефона (`streamer-pack/remote/page/`)

`index.html`, `remote.css`, `remote.js`, `crypto.js` (AES-GCM, deflate, base64url — чистые функции, проверяются в
Node), `aes-gcm.js` (AES-256-GCM на чистом JS, когда браузер не даёт `crypto.subtle`), `render-dock.js` (плейлист из снимка — та же разметка и логика, что `src/dock2.js` ядра), `poll-plan.js` (расписание опроса — чистые функции),
`config.js` (список облаков), `app.css` (копия
`src/app.css` ядра, кладёт скрипт синхронизации; тема — переменными из `snap.theme.vars` на `<html>`).
Адрес страницы: `#<sid>.<ключ>.<номер облака>`; номер 0 можно не писать.
Шапка: точка связи, «Тапёр», поле поиска (выдача — поверх, как в док-панели). Вкладки «Плейлист» / «Сообщения N».
Подвал: назад / играть-пауза / вперёд, что играет, время. Пальцем: кнопки ≥ 40 px, перетаскивание — долгим нажатием
на ручку строки, ⛔ — только если включено в Тапёре (`snap.opts.ban`), «Убрать» — без подтверждения (как в окне).
Горизонтально (`orientation: landscape` и ширина ≥ 640) — две колонки. Связь пропала > 5 с — «Нет связи с Тапёром»;
сессия удалена — «Пульт отключён в Тапёре. Отсканируй новый QR-код».

## Модуль (`streamer-pack/remote/src/`)

`index.js` (`activate(core)`, команды `status/start/stop/renew/mode/lan-ip`), `session.js` (жизнь сессии, опрос, подписи, отбор
команд, переход на запасное облако), `crypto.js` (общий с страницей формат; Node `crypto`/`zlib`), `relay.js` (запросы к
одному облаку, тайм-аут 8 с, повтор с паузой 2–30 с, `fetch` передаётся снаружи — для тестов), `clouds.js` (список
облаков и выбор первого ответившего), `poll.js` (расписание опроса Тапёра — чистые функции), `lan-relay.js` (сервер
режима Wi-Fi: логика ящика, хранилище в памяти, страница телефона), `netinfo.js` (домашние адреса, сети, VPN и
виртуальные адаптеры, профиль сети Windows), `filter.js` (снимок для телефона: без `look`,
без `/lcover` обложек, `feedHtml` — последние 30 карточек). Состояние: `idle | starting | waiting (QR показан) |
connected | lost | error` + `phoneAgo`; `notice` — просьба отсканировать новый QR после перехода на запасное
облако, `cloud: { index, count }` — какое облако и сколько их. Нет `core.remote` (старое ядро) — `error: 'Обнови Тапёр'`.
Ключ `K` и `host` — только в памяти; после перезапуска Тапёра — новая сессия (QR заново).

## Режим Wi-Fi (без облака) — решение владельца 16.11

Второй способ подключения: телефон и ПК в одной домашней сети, облако не участвует. Включается в том же разделе
настроек переключателем «Через интернет / По Wi-Fi» (по умолчанию — «Через интернет»).

**Как устроено.** Модуль пака поднимает **отдельный** маленький сервер (не основной сервер Тапёра на 127.0.0.1!) только на
адресе домашнего адаптера (Wi-Fi/Ethernet), порт 47660 (занят — следующий свободный), и **только пока включён режим и
идёт сессия**. Этот сервер = та же логика ящика, что облачная функция (`server/yc-remote/core.js` + хранилище в памяти —
копия кода в паке `remote/src/lan-relay.js`), плюс раздача страницы телефона из `remote/page/`. QR ведёт на
`http://<адрес ПК>:<порт>/#<sid>.<ключ>`. Протокол, шифрование, команды — **те же**, что через облако.

**Шифрование по простому http.** На странице, открытой по `http://192.168…`, браузер не даёт `crypto.subtle`.
Поэтому `page/crypto.js`: есть `crypto.subtle` — WebCrypto; нет — встроенная реализация AES-256-GCM на чистом JS
(`page/aes-gcm.js`, проверяется векторами NIST и сверкой с Node `crypto`). Формат куска тот же. Сжатие — `CompressionStream`
(есть и без https); нет его — без сжатия, флаг в куске.

**Чужой в той же сети** (гостевой Wi-Fi, общежитие) без QR ничего не сделает: всё зашифровано ключом из QR.
Сервер принимает только адреса из частных сетей (10/8, 172.16/12, 192.168/16, 169.254/16, fd00::/8), лимиты как у облака.

**VPN и прочие помехи — что показывает Тапёр.** Раздел умеет сам находить и объяснять:
1. **Адрес ПК в домашней сети** и сеть целиком (`192.168.1.5`, `192.168.1.0/24`) — крупно, с кнопкой «Скопировать».
2. **VPN на ПК**: в списке адаптеров есть туннель (WireGuard, Wintun, TAP, OpenVPN, «VPN» в имени) и/или маршрут по
   умолчанию идёт через него → подсказка: «Включён VPN. Если телефон не подключается — добавь в исключения VPN
   (split tunneling) программу Тапёр или сеть `192.168.1.0/24`, либо включи в VPN „Разрешить локальную сеть“».
   Сеть для исключения — с кнопкой «Скопировать» (как список сетей Яндекса в `src/ui/27-vpn.js`).
3. **VPN на телефоне** — подсказка всегда, рядом с QR: «Если на телефоне включён VPN — включи в нём „Разрешить
   локальную сеть“ или добавь в исключения адрес `192.168.1.5`».
4. **Брандмауэр Windows**: при первом включении Windows спросит разрешение — подсказка «нажми „Разрешить“ для частных
   сетей». Если сеть в Windows помечена «Общедоступная» (PowerShell `Get-NetConnectionProfile`, только чтение) —
   подсказка, как сменить на «Частная».
5. **Самопроверка**: Тапёр сам обращается к своему серверу по домашнему адресу (`http://192.168.1.5:47660/ping`).
   Не ответил — «Сервер не отвечает по домашнему адресу: мешает VPN на ПК или брандмауэр» + подсказки выше.
   Телефон не пришёл за 60 с после показа QR — «Телефон не подключился: он в той же сети? VPN на телефоне? Гостевой
   Wi-Fi?» и кнопка «Подключить через интернет».
6. Несколько адаптеров (Wi-Fi + Ethernet + виртуальные Hyper-V/VirtualBox) — берём адаптер маршрута по умолчанию без
   туннеля; виртуальные не показываем; есть выбор адреса из списка.

Обойти VPN за пользователя Тапёр **не может и не должен** (менять маршруты Windows и настройки чужой программы — нет):
только найти, объяснить и дать скопировать нужное.
