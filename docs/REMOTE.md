# Пульт Тапёра с телефона (модуль пака `remote`)

Статус: архитектура и план 16.11.2026 (Claude). Макет — артефакт «Пульт с телефона» (ссылка в отчёте сессии).
Основа — вторая док-панель (`docs/DOCK2.md` в ядре, ветка `dock2`): тот же снимок и те же команды.

## Что видит стример

1. Настройки → Модули → «Пульт с телефона» → **«Подключить телефон»**. Тапёр создаёт **сессию в интернете**
   и показывает QR-код (крупно, в окне настроек — **не на стриме**: кто отсканировал, тот управляет).
2. Телефон сканирует QR → открывается страница `https://<сайт Тапёра>/remote/#…` → через 1–2 с там тот же пульт:
   общая шапка (поиск, связь), **вкладки «Плейлист» и «Сообщения»** (это две док-панели OBS), общий подвал
   (назад / играть-пауза / вперёд, что играет, время). Телефон **вертикально** — вкладки; **горизонтально** —
   обе панели рядом, без вкладок.
3. В Тапёре видно «Телефон подключён · 2 с назад». Кнопки «Новая ссылка» (старый QR перестаёт работать) и
   «Отключить» (сессия удаляется). Сессия сама истекает через 12 ч без Тапёра.

## Как устроено (три части)

```
 Тапёр (ПК)                               облако (Яндекс)                      телефон
 окно ──снимок/лента──► узел dock2 ──► модуль remote ══шифр══► функция tapyor-remote ◄══шифр══ страница /remote
       ◄──команды─────            ◄──                   (YDB: ящики,       (GitHub Pages сайта)
                                                         ничего не понимает)
```

1. **Ядро** (ветка `remote` поверх `dock2`): мост для модулей `core.remote`:
   - `dock` = `hub.forModule(id)` (снимок пульта, команды, поиск — `docs/DOCK2.md`);
   - `feed` — лента сообщений первой панели: `on(fn)` (тот же объект `widgetState`, что получает `/widget`:
     `feedHtml`, `msgCount`, `reqAuto`, `np`, `dockClass/dockStyle`), `want(bool)` (считается зрителем первой панели —
     окно начинает собирать ленту), `rq(dataset)` (как `POST /widget/rq`, окно не поднимается), `setting('reqAuto', bool)`;
   - `qr(text)` → SVG-строка (пакет `qrcode-svg`, уже есть в ядре);
   - раздел настроек `src/ui/35-remote.js` + разметка в «Модули» (как «Оверлей-плейлист»), общение — `modCmd('remote', …)`.
2. **Облачная функция `tapyor-remote`** (`server/yc-remote` в ядре, Node 22, YDB — как `yc-license`): тупой почтовый
   ящик. Видит только зашифрованные куски, не знает ключа, не знает, что внутри.
3. **Пак** (`streamer-pack/remote/`): модуль в главном процессе (сессия, шифрование, опрос функции, выполнение команд
   через `core.remote`) и **страница телефона** `remote/page/` (публикуется на сайт `tapyor-web/remote/`
   скриптом `tools/sync-remote-page.mjs` — только по команде владельца).

## Безопасность

- Ключ сессии `K` — 32 случайных байта, создаёт Тапёр, живёт **только** в QR и в памяти Тапёра. В адресе он стоит
  после `#` — браузер **не отправляет** эту часть ни на сайт, ни в функцию.
- Всё содержимое (снимок, лента, команды, выдача поиска) — **AES-256-GCM**: `iv` 12 случайных байт,
  `aad = sid + '|' + вид` (`s` — снимок, `f` — лента, `e` — событие, `c` — команда), кусок = base64url(`iv ‖ шифр+тег`).
  Перед шифрованием — сжатие `deflate-raw` (Node `zlib`, на телефоне `CompressionStream`).
- Команда телефона несёт `n` (8 случайных байт) и `t` (время телефона). Тапёр отвергает: не расшифровалась,
  `t` старше 120 с или из будущего > 60 с, повтор `n` (помним последние 1000). Команды — только из белого списка
  `docs/DOCK2.md` + `rq`/`setting` для ленты (проверяет ещё и узел ядра).
- Право писать снимок и читать команды — у владельца сессии: токен `host` (32 байта), функция хранит только его SHA-256.
- Функция: лимиты частоты (на адрес и на сессию), размер куска ≤ 64 КБ (снимок/лента), ≤ 2 КБ (команда), очереди
  ≤ 50 команд и ≤ 30 событий, срок жизни 12 ч (TTL в YDB). В её лог — только виды запросов и коды ответов.
- В QR — адрес сайта Тапёра. Страница — `script-src 'self'`, без сторонних скриптов и аналитики; ленту (`feedHtml`)
  вставляет только после того, как вырежет `<script>`, `on*=`, `javascript:` (и CSP их всё равно не исполнит).
- Обложки — только `https:`; свои файлы с ПК (`/lcover/…`) телефону не отдаются (заглушка).

## Протокол функции (версия 1)

База — адрес функции (`remote/relay.json` в паке: `{ "url": "https://functions.yandexcloud.net/<id>" }`; пусто — модуль
пишет «облако пульта не настроено»). Все тела — JSON, `sid` — 22 знака base64url (16 байт), `host` — 43 знака.

| Запрос | Кто | Тело / параметры | Ответ |
|---|---|---|---|
| `POST ?op=new` | Тапёр | `{}` | `{ sid, host, ttl }` — новая сессия |
| `POST ?op=host` | Тапёр | `{ sid, host, s?, f?, ev?: [кусок…≤10], ack?: seq }` | `{ cmds: [{ seq, c }], phoneAgo: мс\|null }` |
| `GET ?op=poll&sid=…&sv=N&fv=N&es=N` | телефон | — | `{ sv, s?, fv, f?, ev: [{ seq, e }], hostAgo }` — `s`/`f` только если новее |
| `POST ?op=cmd` | телефон | `{ sid, c: кусок }` | `{ ok: true }` |
| `POST ?op=end` | Тапёр | `{ sid, host }` | `{ ok: true }` |

`s` — снимок пульта, `f` — лента, `ev` — события (выдача поиска, toast). Номера версий `sv/fv` и `seq` ведёт функция.
`ack` — последний принятый `seq` команды (функция удаляет принятые). Ошибки — `{ error, tapyor_error }` как у других
функций (`server/common/reply.js`); 404 `no-session` — сессии нет (истекла или «Отключить»).
CORS: `Access-Control-Allow-Origin` = `PAGE_ORIGIN` (переменная функции, например `https://alexshikaka.github.io`) для `poll`/`cmd`;
для `new`/`host`/`end` CORS не нужен (зовёт Node).

Таблица YDB `remote_sessions`: `sid` (ключ), `host_hash`, `s`, `sv`, `f`, `fv`, `ev` (JSON-массив последних 30), `es`,
`cmds` (JSON-массив ≤ 50), `cs`, `host_at`, `phone_at`, `exp` (TTL). Запись — в одной транзакции (serializable).

## Частота опроса (бережём облако)

- Тапёр (`host`): телефон был < 30 с назад — раз в 1 с; иначе — раз в 5 с; снимок и лента уходят **только когда
  поменялись** (подпись без времени), иначе запрос без `s`/`f`. Нет телефона 2 ч — опрос раз в 30 с.
- Телефон (`poll`): страница видна — раз в 1 с; скрыта (`visibilitychange`) — не опрашивает.
- Нажатие на телефоне → `cmd` сразу, затем внеочередной `poll` через 400 мс. Ожидаемая задержка 1–2 с.
- Развитие (не сейчас): WebSocket через API Gateway или прямая связь WebRTC (опыт — `tapyor-web/remote-test`),
  когда задержка 1–2 с станет мешать.

## Страница телефона (`streamer-pack/remote/page/`)

`index.html`, `remote.css`, `remote.js`, `crypto.js` (AES-GCM, deflate, base64url — чистые функции, проверяются в
Node), `render-dock.js` (плейлист из снимка — та же разметка и логика, что `src/dock2.js` ядра), `app.css` (копия
`src/app.css` ядра, кладёт скрипт синхронизации; тема — переменными из `snap.theme.vars` на `<html>`).
Шапка: точка связи, «Тапёр», поле поиска (выдача — поверх, как в док-панели). Вкладки «Плейлист» / «Сообщения N».
Подвал: назад / играть-пауза / вперёд, что играет, время. Пальцем: кнопки ≥ 40 px, перетаскивание — долгим нажатием
на ручку строки, ⛔ — только если включено в Тапёре (`snap.opts.ban`), «Убрать» — без подтверждения (как в окне).
Горизонтально (`orientation: landscape` и ширина ≥ 640) — две колонки. Связь пропала > 5 с — «Нет связи с Тапёром»;
сессия удалена — «Пульт отключён в Тапёре. Отсканируй новый QR-код».

## Модуль (`streamer-pack/remote/src/`)

`index.js` (`activate(core)`, команды `status/start/stop/renew`), `session.js` (жизнь сессии, опрос, подписи, отбор
команд), `crypto.js` (общий с страницей формат; Node `crypto`/`zlib`), `relay.js` (запросы к функции, тайм-аут 8 с,
повтор с паузой 2–30 с, `fetch` передаётся снаружи — для тестов), `filter.js` (снимок для телефона: без `look`,
без `/lcover` обложек, `feedHtml` — последние 30 карточек). Состояние: `idle | starting | waiting (QR показан) |
connected | lost | error` + `phoneAgo`. Нет `core.remote` (старое ядро) — `error: 'Обнови Тапёр'`.
Ключ `K` и `host` — только в памяти; после перезапуска Тапёра — новая сессия (QR заново).
